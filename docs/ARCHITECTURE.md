# Рішення для Linux

Базовий код: wawimundo/viber-mcp, `af1d0ed1b880dc28a18f2d5198a4d09b52047bd4`.
Використано існуючий приватний Linux-порт, `da06874c901521845575dd7c7eabc9524c5771ac`.

## Що дає оригінал

11 MCP tools; розділення backend і предметної логіки; контакти-аліаси;
відкриття через viber URI; macOS Quartz input та Vision OCR. Windows — scaffold,
Linux не реалізований. Ліцензія MIT та авторство збережені.

В оригіналі `_wait_for_sendable_chat` може прийняти placeholder, перший токен імені
будь-де на екрані або спливання таймера за підтвердження адресата.
`_text_landed` видаляє все, крім ASCII, і повертає True для короткої сигнатури:
це некоректно для українського/emoji-only тексту. `reply` надсилає в поточний чат
без явного адресата; search приймає неоднозначний prefix/substring. Ці шляхи не
використовуються у Linux entrypoint.

## Реалізація

```
Hermes → MCP stdio → async tools → Service (mutex + flock + approval ledger)
                                      ├─ LinuxBackend → AT-SPI worker
                                      └─ X11Backend → X11 worker → Tesseract / xdotool / xclip
```

MCP запускається тим самим користувачем, що й Viber, на VPS. Порт TCP не потрібен.
Інші MCP-клієнти також можуть запускати stdio-команду; для іншого хоста можливий
SSH stdio з окремо налаштованим доступом. Не запускати GUI-backend від root.

AT-SPI пріоритетний там, де Viber експортує потрібні елементи. X11 — явний opt-in,
а не автоматичний повтор після невизначеної дії. Вибір `VIBER_BACKEND` фіксується
на старті MCP. X11 читає лише явно калібровану область; фото існує тільки в RAM.
Локальний Tesseract підтримує українську, англійську та російську.

Немає LLM-викликів усередині backend, запуску браузера чи доступу до ключів Viber.
База на перевірених хостах не мала SQLite-заголовка; схема/дешифрування не припускаються.

## Швидкодія та чесні гарантії

- `read_visible` — одна операція: capture → OCR → компактний результат із `elapsed_ms`.
- stdio-сервер живе протягом MCP-сеансу. Worker короткоживучий, має timeout.
- Блокувальна робота винесена через `asyncio.to_thread`: MCP ping і stop не чекають OCR.
- Немає stale cache: результат читання відповідає новому кадру.
- Немає фіксованих багатосекундних sleep перед кожним читанням.
- Зміна active window, власника або геометрії зупиняє дію. Wayland відхиляється.
- Буфер: тільки сумісний plaintext; HTML, зображення й невідомі MIME відхиляються.
  Відновлення — у `finally`; SIGTERM дає час на cleanup. SIGKILL/crash системи
  не дозволяє гарантувати відновлення. Потрібен окремий, неконкурентний desktop.
- X11 не має stable message ID/outgoing metadata. Після кліку повертається
  `unknown`, `sent:null`, `delivered:null`, а не вигаданий `sent:true`.
  Це означає «можливо надіслано, перевір вручну», а не «повтори».

## Обсяг підтримки

Читання видимих областей працює незалежно від типу чату. Історія поза екраном,
вкладення, дзвінки, фоновий inbox/Webhook і автоматичне A2A через Viber не реалізовані.
Написати довільному контакту можна лише коли вдалося окремо підтвердити точний
номер у каліброваній identity-області. Назви груп/контактів не доводять ідентичність.
My Notes в X11 блокується: незалежного self-маркера немає. Для цих випадків
зберігається читання та ручне надсилання. API parity 11/11 не означає desktop E2E parity.
